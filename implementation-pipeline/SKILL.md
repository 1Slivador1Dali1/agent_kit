# Пайплайн реализации

Скилл работает только когда его прикрепили к промпту. Сам не стартует и автоскиллы репозитория не заменяет.

Родитель ведёт прогон: при отсутствии `.cursor/project.md` записывает вид и стек, пишет анализ, планы, проработку по видам и бриф класса, по слову «ревью» запускает одного ревьюера, сдаёт результат, по подтверждению делает коммит. Боевой код родитель не пишет. Код пишется в отдельном чате, куда пользователь вставляет бриф и сам выбирает модель. После отказа пользователя код правит ревьюер.

Правила репозитория (`AGENTS.md`, `.cursor/rules`) соблюдать во всём, кроме гейтов этого файла. Гейты не снимают слова «сразу», «без вопросов», «не спрашивай» и формулировки вроде «вопросы почти на каждый промпт» или «после плана сразу код». Пока скилл прикреплён: вопросы только по [analysis.md](analysis.md), боевой код в этом чате не писать. Исполнителей не запускать.

Короткий пример хода — [examples.md](examples.md).

## Прогон

Каталог только этого запуска:

`.cursor/plans/pipeline/<YYYY-MM-DD-HHMM>-<slug>/`

Файлы: `state.md`, `00-analysis.md`, `01-master.md`, и лишь непустые `small.md`, `medium.md`, `large.md`. Чужие планы вне этого каталога не читать как задание и не удалять.

`state.md`:

```markdown
status: analysis | questions | planning | await-chats | review | await-user | fixing | done
slug:
```

Старые `await-models` и `implementing` читать как `await-chats`.

В начале хода прочитать `state.md` незакрытого прогона (не `done`). Несколько незакрытых — последний по имени каталога, пока пользователь не назвал другой. Нет прогона, а в сообщении есть задача — шаг 1.

| status | Куда |
|---|---|
| analysis | дописать анализ |
| questions | ждать ответы, план не писать |
| planning | дописать общий план, разбивку, дизайн и бриф, затем стоп |
| await-chats | ждать слово «ревью», исполнителей не запускать |
| review | один ревьюер сверяет diff, код не меняет |
| await-user | ждать подтверждение или отказ |
| fixing | ревьюер правит, затем снова сдача |
| done | новый прогон только на новую задачу |

## Шаги

Отмечать в ответе только то, что сделано в этом ходе.

- [ ] 1. Вид проекта, если записи нет; затем анализ задачи
- [ ] 2. Вопросы, если без них результат другой
- [ ] 3. Общий план-чеклист
- [ ] 4. Фильтр и файлы по сложности
- [ ] 5. Проработка дизайна, если клиентское приложение; затем бриф в файле класса
- [ ] 6. По слову «ревью» сверка изменённых файлов
- [ ] 7. Сдача: что реализовано и как проверить
- [ ] 8. Подтверждение → коммит и удаление планов прогона; отказ → ревьюер правит

Читать один файл текущего шага:

| Шаг | Файл |
|---|---|
| 1–2 | [analysis.md](analysis.md) |
| 3–5 | [plan.md](plan.md) |
| `await-chats` без слова «ревью» | [implement.md](implement.md) |
| 6 и отказ на шаге 8 | [review.md](review.md) |
| 7–8 | [handoff.md](handoff.md) |

## Запрещено

- Писать боевой код родителем
- Писать код в ходе, где статус стал `await-chats`
- Запускать исполнителя реализации и передавать ему `model`
- Спрашивать slug и подставлять модель, которую пользователь не написал
- Пушить
- Удалять каталог прогона до успешного коммита
- Запускать исполнителя или ревьюера в облаке, пока пользователь сам не просил облако
- Называть этот запуск роем: отдельные команды «рой» и `swarm` не нужны

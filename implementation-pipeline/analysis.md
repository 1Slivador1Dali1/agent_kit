# Шаги 1–2. Анализ и вопросы

## 0. Вид проекта

До анализа прочитать `.cursor/project.md` в корне репозитория задачи.

Файл есть — не переписывать. Виды брать из него.

Файла нет — определить виды по манифестам проекта. Папку `agent-kit` признаком не считать: в ней лежат все пакеты сразу.

- Веб — в `package.json` среди `dependencies` или `devDependencies` есть `react`, `vue`, `svelte`, `next`, `nuxt` или `@angular/core`.
- Десктоп — есть `electron`, `tauri`, `@tauri-apps/api`, или `*.csproj` с `UseWPF` или `WinUI`.
- Бэкенд — есть `go.mod`, `pyproject.toml`, `pom.xml`, `build.gradle`, или в `package.json` есть `express`, `fastify`, `@nestjs/core`, `koa`, `hono` и при этом нет признака веба.
- Мобилка — есть `react-native`, `expo`, в `pubspec.yaml` есть `flutter`, или каталоги `android` и `ios` лежат вместе.

Несколько видов записать все, не спрашивать. Стек — короткая строка: имена манифестов, из которых это видно.

Ни одного признака — файл не писать. Это случай «вид не разобрать». Один вопрос, какие виды включить: веб, десктоп, бэкенд, мобилка, можно несколько. `status: questions`. Анализ не писать, пока нет ответа. После ответа записать файл и в том же ходе перейти к анализу.

```markdown
# Проект

- Виды: веб, десктоп, бэкенд, мобилка
- Стек:
```

## 1. Анализ

Коротко осмотреть код, которого касается задача. Создать каталог прогона и записать `00-analysis.md`:

```markdown
# Анализ

- Задача:
- Готово, когда:
- Не делаем:
- Неясное, что меняет результат:
- Класс прогона (догадка): мелкая | средняя | большая
- Что уже есть в коде и какое правило репозитория это закрывает:
- Виды: из `.cursor/project.md`
```

Класс прогона — догадка по самой тяжёлой части, не обещание файлов разбивки.

Поставить `status: analysis`, пока файл пишется. В ответе пользователю: 4–8 строк анализа и догадка класса. Догадку так и назвать.

## 2. Вопросы

Вопрос задавать только если в «Неясное» есть развилка, от которой меняется результат: граница, пустое и ошибочное поведение, что считать готовым, что не трогать.

Не спрашивать то, что пользователь уже написал в этой задаче.

Если неясного нет — в `00-analysis.md` строка `Вопросы не нужны:` и одна фраза почему. `status: planning`. В том же ходе перейти к шагам 3–4.

Если неясное есть:

- 1–5 вопросов за проход
- если доступен инструмент готовых вариантов — им; у каждого вопроса первый вариант с пометкой «(рекомендую)»
- `status: questions`
- ход закончить, план не писать

После ответов, до плана, пересказать договорённость в 2–4 предложениях: что делаем, чего не делаем, что считается готовым. Догадку пометить как догадку. Второй проход вопросов — только если новый факт меняет результат.

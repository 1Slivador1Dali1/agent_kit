# Шаг 6 и отказ на шаге 8

Ревьюер — один субагент `generalPurpose` на весь прогон. Поле `model` не передавать: ревьюер идёт на модели этого чата. Облако не задавать.

Бриф самодостаточен. Ревьюер не видит чат.

## Первая сверка

Вход из `await-chats`, когда в сообщении есть слово «ревью».

`status: review`. Один ревьюер на все непустые классы и изменённые файлы. Первая сверка код не меняет.

Сверять git diff рабочего дерева и новые файлы задачи с `01-master.md` и с каждым непустым файлом класса.

```text
Режим: сверка
Репозиторий: <абсолютный путь>
Каталог прогона: <путь>
Общий план: 01-master.md
Планы классов: <файлы непустых классов>

Код не менять. Посмотри git diff и новые файлы задачи. По каждому пункту плана: сделано или расхождение, с путём файла или командой. Если в плане класса есть «Проработка дизайна», «Проработка десктопа», «Проработка бэкенда» или «Проработка мобилки» и это не строка пропуска, сверь изменения с этой секцией.
Статус: PASS или ISSUES.
Проблемы: одна строка на расхождение или «нет».
```

Результат записать в `review.md` каталога прогона, не в файл скилла. Затем шаг 7, даже если статус `ISSUES`: пользователь видит расхождения до правок.

## Отказ пользователя

Вход из `await-user`, когда нет слова подтверждения, а есть отказ или замечания (`не подтверждаю`, `есть правки`, `не то`, `верни`, `исправь` и любой конкретный дефект).

`status: fixing`. Один ревьюер на все замечания этого сообщения. Он сам вносит правки и снова сверяет. Двух пишущих ревьюеров на один отказ не запускать. Поле `model` снова не передавать.

```text
Режим: правки
Репозиторий: <абсолютный путь>
Каталог прогона: <путь>
Общий план: 01-master.md
Планы классов: <файлы непустых классов>
Замечания пользователя, дословно:
<текст>

Исправь только эти замечания и расхождения с планом. Новое поведение вне плана не добавлять.
Затем сверься с общим планом и планами классов ещё раз.
Не делать git commit и push.

Отчёт:
- Статус: PASS | ISSUES
- Что изменено: пути
- Пункты: номер — сделано или расхождение
- Проблемы: одна строка или «нет»
```

После отчёта снова шаг 7 и `await-user`. Сам второй круг правок не начинать: следующий круг только по новому сообщению пользователя. Коммит не делать.

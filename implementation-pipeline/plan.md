## 3. Общий план

`01-master.md` собирается из анализа и ответов. Один пункт — один наблюдаемый результат.

```markdown
# Общий план

## Договорённость

Что делаем, чего не делаем, что считается готовым.

## Пункты

### 1. Название

- Класс: мелкая | средняя | большая
- [ ] Готово, когда:
- Файлы:
- Не трогать:
- Зависит от: нет | номера пунктов
- Проверка:

## Отфильтровано

- пункт — причина
```

Класс пункта, ровно один:

| Класс | Когда |
|---|---|
| Мелкая | 1–2 файла, нет нового экрана, маршрута, сущности, модалки и нового контракта API |
| Средняя | 3+ файла, или новый блок на уже существующем экране, или вызов уже существующего API в одном месте. Нового экрана и новой сущности нет |
| Большая | новый экран, маршрут или сущность; несколько независимых зон; смена устройства фичи |

Пункт, в котором есть и мелкая правка, и признак большой, целиком большая. Один результат на два класса не резать. Если пользователь в задаче сам назвал класс — его класс сильнее этой таблицы.

Проверка пункта — команда или шаг, по которому видно «готово». Если правила репозитория требуют сначала красный тест — в пункт входит путь теста и команда прогона. Новый тест-раннер не ставить. Менеджер пакетов — тот, который задан репозиторием.

В ответе показать договорённость и список пунктов с классом. Не спрашивать второе «можно писать план?».

## 4. Фильтр и файлы

Перед записью файлов сложности вычеркнуть пункт, если он вне «Не делаем», повторяет другой пункт или уже выполнен и задача его не меняет. Каждый вычеркнутый пункт — строка в «Отфильтровано» с причиной. Молча не выкидывать.

Оставшиеся пункты разложить по файлам:

| Класс | Файл | Заголовок |
|---|---|---|
| мелкая | `small.md` | `# Мелкая` |
| средняя | `medium.md` | `# Средняя` |
| большая | `large.md` | `# Большая` |

Пустой класс не создавать. В каждом файле те же поля пункта, что в общем плане, и ссылка на номер пункта в `01-master.md`.

## 5. Проработка по видам проекта

После файлов классов и до секции «Бриф для чата». Боевой код не писать. Тексты скиллов в этот пайплайн не копировать: читать их из репозитория. Правила репозитория (`AGENTS.md`, `.cursor/rules`) сильнее пакетов. Отсутствующий файл скилла не заменять выдуманными правилами. Если в проекте уже есть свои панели, токены, цвет или устройство — следовать им и второй шаблон не заводить.

Виды брать из `.cursor/project.md`. Нет файла — вернуться к шагу 0 в [analysis.md](analysis.md), планы классов не закрывать.

Пакет читать с первого пути, который есть:

| Вид | Секция | Правило | Пути |
|---|---|---|---|
| веб | Проработка дизайна | `rules/design.mdc` | `agent-kit/front/`, затем `.cursor/skills/` |
| десктоп | Проработка десктопа | `rules/desktop.mdc` | `agent-kit/des/`, затем `des/` |
| бэкенд | Проработка бэкенда | `rules/backend.mdc` | `agent-kit/back/`, затем `back/` |
| мобилка | Проработка мобилки | `rules/mobile.mdc` | `agent-kit/mob/`, затем `mob/` |

Вида нет в `.cursor/project.md` — секцию в файлы классов не писать. В `01-master.md` одна строка пропуска: для веба `дизайн пропущен: не клиентское приложение`, для остальных `десктоп пропущен`, `бэкенд пропущен`, `мобилка пропущен`.

Вид есть — прочитать правило пакета и скиллы, на которые оно ссылается. В каждый непустой файл класса, выше брифа, свою секцию:

- Пункты класса этот вид не затрагивают — одна строка: для веба `видимого UI нет`, для десктопа `десктопной поверхности нет`, для бэкенда `серверного кода нет`, для мобилки `мобильной поверхности нет`.
- Затрагивают — короткие решения по порядку из правила пакета, без пересказа скиллов целиком. Для веба, если система уже есть, новый тон, палитру и шрифт не выдумывать. Для веба с новым экраном и без системы — направление, токены, состояния, движение только там, где оно объясняет изменение, Нильсен и доступность.

Затем в каждый непустой файл дописать секцию «Бриф для чата». Модель в ней не называть. Пустому классу бриф не писать.

```markdown
## Бриф для чата

Скопируйте текст ниже в новый чат. Модель выберите в том чате.

Класс: мелкая | средняя | большая
Репозиторий: <абсолютный путь>
Каталог прогона: <путь>
Общий план: 01-master.md
План этого класса: small.md | medium.md | large.md

Сделай только пункты этого файла выше секции «Бриф для чата». Готово, когда выполнен каждый «Готово, когда». Если выше есть секции проработки — соблюдай их. Строка «видимого UI нет», «десктопной поверхности нет», «серверного кода нет» или «мобильной поверхности нет» значит эту часть не раздувать.

Не трогать:
- пункты других классов
- файлы из «Не трогать»
- каталоги планов, кроме пометок [x] в своём файле и в тех же пунктах 01-master.md
- git commit и push

Порядок: если пункт или правила репозитория требуют красный тест — сначала тест и красный прогон, потом код до зелёного. Команду прогона взять из пункта. Менеджер пакетов — из правил репозитория.

Прочитай AGENTS.md и .cursor/rules, если они есть, и соблюдай их. Видимую поверхность прогони по правилу usability этого репозитория; Critical и Major закрой до отчёта.

Отчёт:
- Статус: PASS | ISSUES | BLOCKED
- Что изменено: пути
- Проверка: команда и итог
- Пункты плана: номер — сделано или нет
- Проблемы: одна строка на проблему или «нет»
```
